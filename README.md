# ↗ Паркур знаний / Knowledge Parkour

Браузерная игра об open source: выбери правильную платформу, перепрыгни пропасть и доберись до финиша. Чистый HTML, CSS, JavaScript и Canvas 2D — без фреймворков, сборки, аккаунта и внешних ресурсов.

![Скриншот игры](assets/screenshot.png)

## Запуск

Откройте **`index.html`** в современном Chrome, Firefox, Safari или Edge. Установка зависимостей для игры не нужна. Либо запустите локальный сервер:

```sh
python3 -m http.server 8080
```

Откройте <http://localhost:8080>. Для GitHub Pages: загрузите репозиторий на GitHub, выберите **Settings → Pages → Deploy from a branch → main / root**. Имя ветки должно совпадать с вашей основной веткой. Публикация из корня работает без build step; используются относительные пути. Репозиторий подготовлен к публикации, автоматически никуда не отправляется.

## Как играть

1. Выберите тему или микс, длину забега (10, 15 или все вопросы), включите или выключите таймер.
2. Выбирайте ответы кнопками, нажатием на платформу в Canvas, клавишами **1–4** или **A–D** (латинская раскладка).
3. Верный ответ: прыжок, 100 очков и 10 монет. Серия добавляет по 25 очков за шаг, до +125.
4. Ошибка: платформа трескается, рассыпается и персонаж падает. Теряется одна из трёх жизней; игра показывает верный ответ, пояснение и источник. Нажмите «Продолжить».
5. Каждые пять вопросов сохраняется **чекпоинт**. Ошибка возвращает на начало текущего отрезка; до первого чекпоинта — на первый вопрос. Очки за уже пройденные вопросы остаются, повторное прохождение не даёт новых очков и монет. Каждая попытка учитывается в точности и разборе ошибок.
6. После вопросов — **три последовательных прыжка на точность**. Нажмите «Прыжок», пробел, Enter или платформу, когда указатель находится в зелёной зоне. Зона постепенно сужается. Промах отнимает жизнь и возвращает к началу финального участка. Награда за каждый из трёх шагов выдаётся один раз: 50 очков и 5 монет. Отключение таймера вопросов не отключает эту механику.
7. На финише видны очки, точность (верные ответы / все попытки), заработанные монеты и все ошибки с пояснениями. Кнопка «Ещё раз» запускает новый перемешанный набор.

Платформы постепенно отдаляются, начинают менять высоту, двигаться и поворачиваться. В начале предлагаются два ответа, потом три и четыре, если исходный вопрос содержит достаточно вариантов. Вопросы случайно выбираются и перемешиваются внутри возрастающих уровней сложности; ответы перемешиваются с пересчётом верного индекса.

**Esc / Ⅱ** — пауза. В скрытой вкладке и открытом магазине забег приостанавливается. При перезагрузке сохранённый забег открывается на паузе. Кошелёк, купленные скины, эффект золотого следа, рекорд и количество завершённых забегов сохраняются в `localStorage`. Магазин использует только игровые монеты. Данные локальны для браузера и адреса; в режиме `file://` поведение хранилища зависит от браузера. При запрете хранилища игра продолжает работать в текущей вкладке.

## Вопросы и источники

20 вопросов из файла лекций «Location 1 «Остров Open Source» (Op (1).txt» в двух языковых версиях:

- «Остров Open Source»: определения, лицензии, сервисные модели, self-hosting и цифровой колониализм;
- «Город DPG»: стандарт из девяти индикаторов, реестр, OpenStreetMap и DHIS2;
- «Деревня сообщества»: BDFL, меритократия, участие, прозрачность и коммуникация;
- «Гора GitHub»: fork/branch/PR, workflow, коммиты и автоматизация документации.

В каждой лекции пять вопросов. При её выборе меняются палитра и пейзаж: остров с пальмами, город, деревня или горы. В режиме «Всё вперемешку» локация следует теме текущего вопроса. Светлая/тёмная тема переключается независимо. Количество вопросов в забеге ограничивается размером выбранного набора.

У каждого вопроса есть пояснение и ссылка на первоисточник: [OSI](https://opensource.org/osd), [GNU](https://www.gnu.org/licenses/gpl-faq.html), [Git](https://git-scm.com/docs), [GitHub Docs](https://docs.github.com), [SemVer](https://semver.org/). Короткие пояснения предназначены для обучения, а конкретные обязанности определяются текстом применимой лицензии.

**Силлабус `Introduction to OS_Gerassimov M.pdf` не был предоставлен в рабочей папке.** Набор составлен по темам из задания, без утверждения о соответствии отсутствующему документу. После добавления PDF следует сверить темы и дополнить набор.

### Добавить вопросы

Редактируйте `questions/ru.json` и `questions/en.json` по [CONTRIBUTING.md](CONTRIBUTING.md) и [JSON Schema](questions/schema.json). Затем:

```sh
python3 scripts/bundle-data.py
```

`questions/*.json` — единственный редактируемый источник вопросов, `i18n/*.json` — интерфейса. `js/bundled-data.js` — автоматически создаваемая копия для `file://`, где браузер блокирует `fetch` локальных JSON. При HTTP-запуске вопросы читаются непосредственно из JSON; при ошибке чтения используется копия. Интерфейс использует генерируемые словари для одинакового поведения в обоих режимах.

### Загрузить свой набор

Раскройте «Загрузить свои вопросы» и выберите JSON-файл либо HTTPS URL. Сервер URL должен разрешать CORS для адреса игры (для `file://` — origin `null`; обычно используют `Access-Control-Allow-Origin: *`). Запросы не передают credentials. До 500 вопросов и 2 МБ, ограничение URL-запроса — 10 секунд. Загружается массив объектов формата из CONTRIBUTING. После загрузки автоматически выбирается «Свой набор». Он хранится в памяти вкладки; вопросы начатого забега сохраняются вместе с прогрессом. Собственный набор не переводится автоматически при смене языка интерфейса.

Импорт валидирует обязательные поля, непустые ответы, уникальность ID, сложность, верный индекс и безопасные HTTP(S)-ссылки. Текст вставляется через `textContent`, без выполнения HTML.

## Доступность и оформление

Русский и английский, автоматическая светлая/тёмная тема с ручным переключением, адаптивная вёрстка от 360 px. Ответы Canvas дублируются настоящими кнопками; результаты объявляются через `aria-live`. Есть видимый фокус, доступные диалоги и управление с клавиатуры. При `prefers-reduced-motion` отключаются движения платформ, частицы, след и перемещение камеры, прыжки сокращаются. Финальный индикатор сохраняется как элемент игрового тайминга.

## Структура

```text
index.html                 интерфейс и подключение скриптов
style.css                  темы, адаптивность, reduced motion
js/
  questions.js             загрузка, проверка, перемешивание
  physics.js               траектории, движение платформ
  renderer.js              Canvas, персонаж, камера, частицы
  game.js                  цикл, состояния, очки, чекпоинты
  ui.js                    интерфейс, магазин, i18n, хранилище
  bundled-data.js          генерируемая копия JSON для file://
questions/{ru,en}.json      20 вопросов на каждом языке
questions/schema.json      JSON Schema 2020-12
i18n/{ru,en}.json           словари интерфейса
assets/                    иконка и скриншоты
scripts/                   генерация, валидация, браузерная проверка
tests/game.test.cjs         тесты логики без зависимостей
.github/workflows/         проверка данных и тесты на push/PR
.github/ISSUE_TEMPLATE/     новый вопрос, ошибка в вопросе, баг
CONTRIBUTING.md
LICENSE                    MIT
```

Скрипты разделены на классические модули в пространстве `Parkour`, а не ES modules: это позволяет запускать игру двойным щелчком без локального сервера.

## Проверки

Для тестов логики нужен Node.js 22+, для проверки схемы — Python:

```sh
node --test tests/*.test.cjs
python3 -m venv .venv
.venv/bin/pip install jsonschema==4.23.0
.venv/bin/python scripts/validate-questions.py
```

GitHub Action дополнительно пересоздаёт `bundled-data.js` и проверяет отсутствие расхождений с JSON.

Опциональная браузерная проверка: запустите отдельный Chrome в headless-режиме с `--remote-debugging-port=9223` и временным профилем, затем `node scripts/browser-check.mjs`. Скрипт проходит реальный игровой сценарий через Chrome DevTools Protocol и сохраняет desktop/mobile скриншоты. Он использует тестовый профиль браузера и очищает localStorage игры в этом профиле. Сторонние npm-пакеты не нужны.
